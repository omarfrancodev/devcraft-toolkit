# Seven-client distribution scenarios

These packets extend the historical four-client matrix without rewriting its
observations. Use actual disposable users/containers or verified client profiles.
No host credentials, personal installations, security bypass or model call is
required for a registration/resource probe. Such probes are limited evidence.

## CLIENT-COPILOT-01: remote suite and shared package

Fetch the public immutable reference independently. In disposable Copilot CLI,
register its remote marketplace, install the qualified suite, list it and compare
all seven installed skill folders and resources with the reference. Confirm no
planned skill is discovered. Record the client version, resolved ref, commands,
hashes and exit codes. Run repeated install, update and scoped removal only in
the owned environment; preserve an unrelated sentinel.

## CLIENT-COPILOT-02: repository scope and VS Code crossover

Start with no user-enabled suite. In a selected trusted repository declare
extraKnownMarketplaces and enabledPlugins in .github/copilot/settings.json.
Observe actual auto-install and invocation/resource reads, then an unrelated
control repository; storage alone is not activation. Repeat with explicit user
enablement and record the difference. Do not use a global enable/disable command
to override a repository overlay.

In an isolated Copilot session in VS Code inspect discovery of the CLI-managed
installation and the UI's selected/workspace enablement separately. Slash-command
and Agent Customizations inventories need not match. A CLI result cannot pass
the VS Code row. Preserve foreign copies and ask when ownership is ambiguous.

## CLIENT-KIRO-01: Power and CLI-only alternative

Use Kiro IDE's actual remote Power import, then a V3 CLI session on the same
isolated user. Enumerate the seven skills and invoke the entry with a bundled
resource read in each client separately. Observe CLI powers-install help: only
catalog name/local path is an established argument; never substitute an untested
GitHub URL. Project-only Power remains not_supported under this contract.

For CLI without the IDE, fetch the explicit full set through the documented
remote Skills CLI route. Compare all resources and then independently check
V3 discovery/invocation in selected/control projects. A full skill set is not a
Power installation. Version/help observations do not pass these session checks.

## CLIENT-CREW-01: complete remote import without a template

In a disposable Crew instance use Settings > Skills > Discover with the public
repository (and a recorded existing ref). Select/import every available skill.
Inspect each actual imported source path, resolved commit and bundled
references/assets; import may confirm each skill separately and is not an atomic
plugin install. Do not confuse skill_fetch's main-file preview with installed
resources. Retain paths/identifiers from discovery rather than constructing the
importer's source-id suffix.

Use the existing default agent with no restrictive skill mappings. Enumerate
the seven owned capabilities, invoke the entry and observe an owned report
writer's reference/template read with English and Spanish supplied-fact requests.
If an existing selected agent restricts its skills, record unavailable mappings;
do not create a template, switch the user's agent, or modify permissions to pass.

## CLIENT-CREW-02: project, collisions and lifecycle

With no global toolkit import, enable and trust one active project containing
the complete .kiro/skills set. Compare an unrelated control project, revoke trust
and verify discovery changes in actual sessions. Do not infer Crew global
discovery from ~/.kiro/skills or a Power cache; its default own store is
~/.kiro/crew/skills.

For user imports, re-import the same repository/ref after explicit replacement
approval, inspect resolved source metadata and retain unrelated content. Remove
only each selected imported directory through supported controls; an existing
agent mapping that references a removed skill must be reported. A Git source
change alone does not update an imported snapshot.
