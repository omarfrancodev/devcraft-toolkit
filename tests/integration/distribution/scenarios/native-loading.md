# Native loading scenarios

Run only in an isolated client profile whose isolation is verified, or an actual disposable user/container. Never copy authentication stores, alter personal plugin state, disable trust/approvals, or use a HOME override as proof of desktop isolation. Preserve exact client/extension versions and actual source revision.

## NATIVE-01: standalone skill

For each target and scope install the selected complete folder (and explicit dependencies when needed). Observe the native discovered identifier, invoke the report writer from supplied facts in English and Spanish, and verify its local reference/template read. Return content only. Check unrelated files and the other scope before/after. Folder presence is insufficient.

## NATIVE-02: native suite

Register the correct local marketplace or import the Kiro Power. Install the suite, enumerate all seven actual skills from client discovery, invoke the entry and route to its owned formatter/report writer. Observe identifiers and ownership rather than supplying synthetic namespace fixtures. Verify bundled resources and language.

## NATIVE-03: scope and control project

Use a selected and unrelated control project. For project scope, prove the selected skills/enablement are absent or inactive in the control. For user scope prove discovery in both. If a global plugin remains installed but is disabled in one project, verify the disable state in that project's actual session. Record storage separately from activation; do not infer scope from shared-cache contents.

## NATIVE-04: lifecycle

In the disposable selected scope only, install again, update through supported client commands/UI and remove the named installation. Capture before/after metadata, resources, settings, discovered lists and unrelated sentinel hashes. Preserve the other scope. Observe reload/restart instructions, actual updated version and removal behavior. Marketplace refresh alone does not prove an installed update.

## NATIVE-05: unavailable environment and Kiro exception

Use blocked for missing authentication, client or verified isolation; not_run for an available but unexecuted route; limited for registration/metadata observations without activation; failed for an actually attempted failed assertion. Kiro project-only native Power is not_supported under the approved interface. Test the full seven-folder project skill-set fallback separately; its filesystem pass does not establish IDE activation.

## Matrix

Four targets × native suite/selected standalone × project/user = sixteen primary rows. Add a distinct Kiro project skill-set fallback row. Initialize not_run except the Kiro project Power exception. Track structural acceptance, filesystem evidence, native discovery/resource/routing, scope and lifecycle independently. A row is passed only when all applicable native assertions ran and passed.
