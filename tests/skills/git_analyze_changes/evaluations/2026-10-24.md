# Analyzer behavior and command evidence

Date: 2026-10-24. Owner: `git-analyze-changes`.
Harness: Codex desktop fresh isolated agent contexts, `gpt-6.1-sol`, medium effort for ten record-shaping samples; high effort for one independent edge/gap replay. These are manually loaded instructions and supplied-fact replays, **not native plugin activation**.

## Method and baseline

The same [fact fixture](../fixtures/analysis-facts.json) and Spanish request were supplied to five fresh controls before the skill existed. Controls were forbidden to read candidate instructions, specs, plans or scoring criteria. Five different fresh contexts then read the complete skill/reference and explicitly selected context dependency. No live repository was attached to the virtual fixture path; actors ran no Git commands or writes.

All five controls correctly distinguished staged rounding work from unstaged debug output, preserved exact names, and did not invent successful tests. Those are baseline successes, not RED failures. All five omitted the reusable analysis contract: no evidence IDs and no explicit outcome/coverage/scope/snapshot structure for composition. This is a record-shaping gap, addressed with a positive field recipe rather than additional disciplinary prohibitions.

Retained verbatim control excerpts:
- Control 1: “Las observaciones aportadas indican que `HEAD`, el índice, el estado y los contenidos inspeccionados permanecieron iguales durante la captura.”
- Control 2: “Hay **preparación parcial** en `src/total calc.py`: el contenido preparado y el contenido actual del archivo difieren.”
- Control 3: “Tampoco puede determinarse la relevancia de los dos archivos sin seguimiento con los metadatos disponibles.”
- Control 4: “un commit del índice actual incluiría el cambio de redondeo, pero excluiría la impresión de depuración.”
- Control 5: “Este análisis se basa exclusivamente en esos datos; no se inspeccionó un repositorio en vivo ni se realizaron modificaciones.”

## Real Git controls

`python -B -m unittest tests.skills.git_analyze_changes.integration.test_inspection_recipes -v` ran seven tests successfully on disposable repositories. They establish:
- Distinct staged/worktree patches for a partially staged path; snapshots unchanged after reads.
- Exact NUL rename destination/source, space/shell-looking names, literal bracket path selection, deletion and binary patch markers.
- External diff/textconv and filesystem-monitor sentinels remain absent with the protective flags.
- Configured clean/process filters select the metadata-only gate; no hashing status/worktree diff or filter execution.
- A same-status content edit changes a raw digest, demonstrating why status alone is insufficient.
- Unborn, detached, conflicted and missing-identity repositories remain inspectable.
- A gitlink appears in index inventory without a submodule directory or recursive traversal.

Fixture setup intentionally stages/configures/commits only in disposable repositories before observation. Read-recipe snapshots include index bytes, Git metadata, refs and worktree content/modes. These are development controls, not evidence that an assistant chose the commands correctly. No real missing-object/promisor remote, external symlink target, or native client activation was exercised; those remain explicit limitations.


## Independent edge/gap replay

The high-effort actor read the complete analyzer/reference/context dependency and answered seven independent virtual cases. A: changed raw guard despite unchanged MM status returned limited and discarded the combined result. B: configured clean/process filters returned limited and excluded status/worktree hashing, including the dependency's optional summary. C: unborn/missing identity allowed inspection without inventing unseen patch behavior. D: a conflict and MERGE_HEAD remained inspectable with planning blockers. E: a missing selected-installation context dependency returned blocked without using the foreign copy. F: unavailable NUL support returned limited; bracket/shell-looking names remained data, symlink target contents and submodule internals uninspected. G: a fully observed empty staged-only scope could return no_op while the worktree remained dirty. No live reads or writes occurred in these replays.

Retained excerpts: A: “The content guard changed (a → b), invalidating the composed result despite equal HEAD, index, and MM status.” B: “Do not run status or worktree diff/content-hashing Git commands, including the context dependency’s optional status summary.” E: “The existence of foreign:git-working-directory-policy does not establish ownership or authorize substituting it.” All seven decisions matched the expected boundary; cases C/D/G explicitly withheld completeness until the missing evidence is observed.
