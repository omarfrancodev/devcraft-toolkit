# Commit planner behavior and fixture evidence

Date: 2026-10-24. Owner: `git-plan-commits`.
Harness: fresh Codex desktop agent contexts, `gpt-6.1-sol`, medium effort for five controls and five complete-instruction samples; high effort for edge/gap replay. All candidate resources and dependencies were manually read. This is not native loading or authenticated invocation.

## Controls before authoring

Five fresh contexts received the same [planning facts](../fixtures/planning-facts.json) without planner instructions, other skills, spec, plan or assertions. Each actor answered the Spanish request using supplied facts only and ran no Git/write operation.

All five correctly grouped staged rounding implementation/tests and excluded unstaged debug plus unknown untracked content. Those are baseline successes. Controls 2 and 3 reused supplied evidence IDs; the rest used filenames/descriptions. None produced the complete reusable top-level/group contract with selection policy, analysis snapshot, dependency order and explicit group fields. The positive record recipe targets that observed output gap, not a claim that general commit judgment was broken.

Retained verbatim control excerpts:
1. “Propongo un commit principal y dejar pendientes los cambios que necesitan revisión.”
2. “La propuesta es limitada: no se ejecutaron validaciones, no se inspeccionó el contenido de los archivos nuevos y no está establecida la identidad del autor.”
3. “La implementación y sus pruebas forman una unidad: ambas corresponden a la precisión decimal de los totales.”
4. “No propondría más commits hasta conocer la finalidad de esos archivos y del mensaje de depuración.”
5. “El archivo `src/total calc.py` está parcialmente preparado: al ejecutar posteriormente el plan, habría que conservar esa separación y evitar incorporar accidentalmente el `print`.”

## Real Git fixture checks

`python -B -m unittest tests.skills.git_plan_commits.integration.test_planning_fixtures -v` passed four tests on Git for Windows 2.45.0.windows.1:
- Existing staged implementation/tests/docs exclude the later same-file debug edit and untracked notes; read snapshots unchanged.
- An empty staged selection coexists with modified/untracked work; no clean-repository inference.
- A changed staged selection invalidates the index digest.
- A later worktree edit invalidates content freshness while HEAD/index remain unchanged.

Only disposable fixture setup mutates Git. These tests verify facts available to a planner, not an executable implementation of grouping judgment. No native client/plugin invocation or automated message semantic scoring is claimed.

## Path-only selection regression — RED

After the branch review recommended clarifying path versus layer precedence, a fresh high-effort actor read the unchanged planner/analyzer/formatter resources. Request: “Plan commits for src/total.py.” Facts: A1 staged rounding fix and A2 unstaged debug in that path; A3 supporting staged tests outside it; supplied stable guards, no explicit layer request.

Observed failure, verbatim: “The explicit path src/total.py takes precedence over the staged-first default. Selected evidence therefore includes A1 staged rounding fix and A2 unstaged debug print.” The actor made G2 pending and asked a layer choice instead of retaining the staged-only default. It correctly excluded A3 and disclosed replay freshness, but the selection broadened incorrectly. The recommendation is now a confirmed selection defect, not a cosmetic wording preference.

Fix: narrow paths first, then apply explicit layers or the staged-first default within those paths; staged work outside the selected paths does not suppress their normal fallback. No runtime executable or mutation was introduced.

## Path-only selection regression — GREEN

A different fresh high-effort actor read the corrected resources and received the same case without assertions. It selected G1/A1 staged only, excluded A2 debug and out-of-scope A3 tests, and required no layer decision. Verbatim: “Restrict to src/total.py, then apply the staged-first default.” It retained limited replay freshness and no write authorization.

A second independent fact case in that fresh context put only unstaged rounding work in src/total.py and staged unrelated docs outside the selected path. The actor selected the scoped unstaged work and excluded the unrelated staged docs. Verbatim: “Its staged state does not suppress fallback inside src/total.py.” Both application checks passed. This is one targeted fresh-context regression, not an additional five-sample reliability claim or native activation result.
