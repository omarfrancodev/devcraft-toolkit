Snapshots prove only allowed index metadata/content changed; excluded worktree/HEAD/refs/config remained unchanged.

Runtime has no Python dependency; these Python fixtures are development evidence.

## Real application and independent verification

A fresh high-effort actor loaded the source skill/dependencies and actually staged the authorized rounding target in an owned ignored fixture. It ran the checked cached patch pair, verified the complete target OID and preserved keep.txt, HEAD/refs, config, hooks and worktree bytes. An independent parent snapshot comparison confirmed that only the index content keys changed.

The explicit complete target required LF bytes/OID21123f5307af8e66377aebb4711ea70175522caa, while the fixture's original base blob used CRLF. The actor disclosed and performed that approved index normalization; it did not normalize or otherwise modify the working file. This tests exact approved bytes, not an implicit line-ending conversion policy. An initial wrong skill-file lookup failed without effects and was corrected before Git execution.

A stricter raw-byte assertion exposed text-mode stdin translation in the development fixture runner. The runner now sends binary input, retains an explicit raw-output option and uses a known LF index baseline for the generic patch control. The target assertion was retained; it was not weakened to accept normalized-but-different data.

Manual source loading and actual Git execution in one controlled harness still do not establish native plugin discovery or general reliability.
