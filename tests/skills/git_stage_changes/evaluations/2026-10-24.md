## Real application and independent verification

A fresh high-effort actor loaded the source skill/dependencies and actually staged the authorized rounding target in an owned ignored fixture. It ran the checked cached patch pair, verified the complete target OID and preserved keep.txt, HEAD/refs, config, hooks and worktree bytes. An independent parent snapshot comparison confirmed that only the index content keys changed.

The explicit complete target required LF bytes/OID21123f5307af8e66377aebb4711ea70175522caa, while the fixture's original base blob used CRLF. The actor disclosed and performed that approved index normalization; it did not normalize or otherwise modify the working file. This tests exact approved bytes, not an implicit line-ending conversion policy. An initial wrong skill-file lookup failed without effects and was corrected before Git execution.

A stricter raw-byte assertion exposed text-mode stdin translation in the development fixture runner. The runner now sends binary input, retains an explicit raw-output option and uses a known LF index baseline for the generic patch control. The target assertion was retained; it was not weakened to accept normalized-but-different data.

Manual source loading and actual Git execution in one controlled harness still do not establish native plugin discovery or general reliability.

## Index-write hook regression — RED

The independent whole-branch reviewer identified that add/cached apply can execute post-index-change before postcondition checks. A fresh real actor used the pinned pre-fix source at 3930ba3 and an owned fixture with custom hooksPath. It performed authorized exact README staging, obtained exit0 and a matching whole-index target, but the index hook rewrote excluded protected.txt. The actor correctly reported stopped afterward; the pre-write preservation requirement had nevertheless failed.

Verbatim baseline: “preservation failed after the actual staging operation.” It reported protected.txt bytes as Unexpected hook rewrite. and preserved the failed state without retry/rollback. Independent parent snapshot comparison confirmed the index change and excluded-file hash change, with HEAD unchanged.

A Git characterization control independently exercised add and cached apply under both default/custom hooks directories. All four combinations invoked the hook; cached --check itself did not. These tests establish why post-write detection alone is insufficient.

Fix: inspect effective/default post-index-change and helpers before every index mutation, including deferrals/restorations; block unknown/out-of-contract effects without bypass. The coordinator's index/commit effect gate now precedes staging and is refreshed before each write.

## Index-write hook regression — GREEN

A different fresh actor used the corrected skill with an independent identical owned fixture. It resolved custom-hooks, read post-index-change and recognized its write to excluded protected.txt. It reported blocked before running add/apply, without disabling hooks. Verbatim: “README.md was not staged.” Independent parent snapshot equality verified every recorded guard unchanged, including index bytes, HEAD/refs, hook/configuration and worktree state. [Before/after evidence](index-hook-regression.json) retains both the real unsafe baseline and blocked corrected execution.

This closes the observed pre-write gap; it does not claim hooks can be made harmless by postcondition checks or that native discovery was tested.
