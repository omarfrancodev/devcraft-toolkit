Harness: fresh Codex desktop contexts; gpt-6.1-sol medium effort for five controls and five candidate record samples, high effort for edge/gap and real application. Complete local source/dependency loading is manual, not native discovery.

## Baseline before authoring

Five fresh controls received only the same [executor transcript](../fixtures/commit-facts.json), no skill/spec/plan/assertions. All preserved G1 membership, excluded debug/notes, actual reported commit/parent and the distinction between worktree validation and selected index evidence. These are successes.

None returned the complete reusable coordinator record with explicit mode/authorization/groups/per-check receipt/commit identity-tree/remaining/state/limitations. The positive record recipe addresses this output-shape gap rather than claiming generic commit safety was broken.

## Five complete-instruction samples

All five different fresh contexts preserved the semantic coordinator fields, G1/actual supplied C1-H1/tree/message/identity, stage no_op, excluded worktree state, validation scope and supplied-evidence provenance. Presentation varied between tables and prose.

Samples 1, 3 and 5 explicitly retained the missing check cwd as unavailable; sample 4 omitted that detail; sample 2 inferred /sample as the cwd from repository context. The latter is an observed receipt-precision failure, not counted as a pass. Added a positive working_directory slot with unknown for unsupplied values; repository root is not execution evidence.

A separate fresh targeted regression on the same facts then returned, verbatim: “working_directory: unknown; no fue suministrado. La raíz /sample no demuestra dónde se ejecutó el comando.” It kept passed/exit0/check ok with the actual supplied worktree scope, without inventing an exact-index check. This targeted correction is not a new five-sample reliability claim.

## Real Git recipe controls

Five disposable-repository tests passed: exact selected tree and literal stdin message, parentless initial commit, failing hook with pending state preserved, an exit-zero hook's extra blob detected against the approved tree, and second-group failure preserving the first commit and pending selection.

Fixture hooks intentionally execute only inside owned repositories; they are test probes, not permission to run uninspected consumer hooks. Binary stdin transport preserves message bytes. Command-semantic tests do not implement or prove coordinator judgment. No runtime Python dependency is added.

## Edge/gap and real application

Ten independent replay cases passed: planning does not authorize writes; unrelated staged entries require approved deferral; unavailable required exact-index validation blocks; later failure preserves earlier actual commits and inspects unknown HEAD effects; unexpected hook content/message stops; unknown hooks/signing and foreign dependencies are not bypassed; stale guards invalidate evidence despite urgency; missing cwd remains unknown; and an explicit one-group commit with no configured check uses not_detected and inline progress without inventing a gate.

A different fresh high-effort actor actually executed one authorized staged-only commit in an owned fixture, manually loading the complete closure. It reported stage no_op, no active hooks/signing, validation not_detected (no configured executable checks), then created and verified a normal commit with the exact UTF-8 stdin message. Excluded debug and untracked notes remained byte-for-byte unchanged; no branch was created and no network operation occurred.

Independent parent checks verified the complete committed tree versus the initial index manifest, exact message/author, one parent matching original HEAD, unchanged residual index, protected worktree/configuration and observed actual commit SHA. [Retained result](live-commit-result.json) records those guards without personal absolute paths. This is real Git execution through manually loaded instructions, not native discovery.

A sixth recipe control explicitly shows that GIT_AUTHOR_NAME/EMAIL can override local config before a write. The coordinator therefore inspects effective author/committer via git var before committing, rather than discovering an identity mismatch only afterward. Required preflight/identity decisions remain unchanged.
