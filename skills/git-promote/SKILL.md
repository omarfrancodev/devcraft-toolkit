# Promote One Existing Request

Assess one selected hosted request and merge it only when expressly requested. An approving comment, completed push, ready result or plan step grants no merge permission.

## Resolve resources and mode

Require the selected installation's `git-manage-pull-request` and its owned `git-working-directory-policy`, using exact discovered identifiers. Missing/foreign dependencies are unavailable; ambiguous copies need a choice. Never install or imitate them, read a runtime root catalog, or require a specific provider plugin.

Default inspect is offline supplied/local evidence only. Explicit hosted observation permits bounded reads. Explicit merge permits necessary reads, one guarded normal merge of the selected existing request and bounded verification. Reuse existing authorization. Missing requests need a decision or separately authorized management creation.

Read [promotion.md](references/promotion.md) before assessment or execution. Use explicit language preference, request language, then English; preserve identifiers and redact secrets.

## Assess and act

1. Delegate necessary observation to the owned management route, preserving canonical host/account/project/request identity, source/target refs/OIDs, coverage and versions. A complete hosted selector needs no Git scan, clean local worktree, commit identity or local publication preflight.
2. Discover actual provider operation/schema and policy support. Keep open/non-draft lifecycle, known mergeability, normal method, source preservation, applicable reviews/checks and authenticated permission together. Gate evidence is satisfied, explicitly not_required, blocked or unknown, with authoritative source and revision scope; empty checks or stale approvals are not success.
3. Refresh identity, OIDs, gates and expected effects immediately before execution. Stop affected mutation on moved source or incompatible method/cleanup/queue effects. Strict target-OID guarantees need actual atomic support.
4. Only an explicit merge request and ready evidence permit one server-enforced full-source-OID conditional operation. Select ordinary merge commit only. No branch deletion, squash, rebase, automatic merge/queue, policy bypass, additional review or local Git writes.
5. Capture the attempt once. Independently observe exact merged state, real merge provenance tied to pinned source and target containment. At most three read observations; pending or failed acknowledgment is not verified merged. Preserve actual effects, without another merge, rollback, cleanup or unattended monitoring.

## Return

Report outcome, mode/authorization, exact owned identifiers, canonical scope, observed source/target versions, method and scoped gates, actual attempt/results, immutable merge provenance separately from mutable target tip, containment, preserved/partial effects and limits. Outcomes: planned, ready, merged, no_op, needs_decision, limited, blocked, stopped, partial, pending, uncertain.

Supplied facts remain reported evidence. A historical merge is not proof of current target containment or deployment. Do not create auxiliary files, publish comments, rerun checks, change credentials or infer release permission.
