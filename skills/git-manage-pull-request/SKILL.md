# Manage One Hosted Request

Manage one exact hosted PR/MR through the available GitHub or GitLab interface. Creation, metadata editing and promotion are separate permissions.

## Resolve installation and intent

Require the selected installation's `git-working-directory-policy` through its exact discovered identifier and ownership. Missing/foreign context is unavailable; unresolved copies need a choice. Never install, imitate or read a runtime root catalog.

Use explicit language preference, request language, then English. Preserve identifiers and redact secrets.

Default proposal uses supplied/local facts only, without provider/network calls or writes. An explicit hosted inspection permits bounded reads. An explicit create permits one selected creation; an explicit update permits one patch of selected title/body fields. Neither grants merge, push, lifecycle changes, approvals or notifications to additional reviewers.

Read [requests.md](references/requests.md) before shaping or executing the flow. It defines identity, provider-interpreted text effects and verification.

## Execute the selected flow

1. Resolve actual provider/host/account, source/target repository identities, refs/OIDs and request selector. Inspect real tool capabilities. Use owned context only for necessary metadata-only local inference; a complete hosted selector needs no Git scan or publish preflight. Local dirtiness or missing Git identity does not block a hosted request.
2. Observe the selected request or a complete exact-match listing. Same branch spelling across forks is not identity; pagination/error/unknown is not absence. Multiple matches need selection. A missing published source never authorizes push.
3. Pin compare/template evidence and its coverage. Use the selected project template or [local fallback](assets/pull-request.md). Describe supported behavior and actual versus supplied/not-run validation; preserve unknowns. Drafting returns content in conversation, not a file.
4. Before create/update refresh identity, refs/OIDs and affected old fields. Existing exact open request on create is no_op, without an inferred edit. Changed fields/scope need a decision. Preserve unselected fields and existing lifecycle/draft state, including title markers and description commands.
5. Submit one authorized operation with literal structured arguments. Independently reread its exact result and preserved state. Failed acknowledgment, source movement or unexpected effects remain partial/uncertain; reconcile by reads without another write, rollback or cleanup.

## Return

Report outcome, mode/authorization, scope and observed versions, request identity, coverage/template/language, proposed or changed fields, actual command/readback results, effects and limits. Outcomes: planned, observed, created, updated, no_op, needs_decision, limited, blocked, stopped, partial, uncertain.

Supplied transcripts remain reported evidence. Matching desired state after a lost acknowledgment does not prove attribution. Create no auxiliary files or external comments. Missing execution tools are distinct from missing required skills.
