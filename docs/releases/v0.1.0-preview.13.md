# Devcraft Toolkit v0.1.0-preview.13

Twenty packaged skills with explicit commit boundaries by intent. Independent
changes in one file can form separate commits, while a single coherent group
must explain how its selected changes share one purpose. The publication flow
keeps these boundaries through verification and push.

The implementation is integrated in PR #16. The release preparation updates the
manifests, current installation references and these notes before its own merge.
The tag and ZIP target that exact release-preparation merge.

## 0.1.0-preview.13 — 2026-11-07

### Added

#### Validation

- Add PW-06 to evaluate two independent intentions in one file, with separate planner groups, exact hunk selections, two verified commits and a single publication to a local bare remote.

### Changed

#### Git operations

- Identify distinct purposes from selected diffs before choosing commit groups, including independent changes within the same file and layer. Require every complete single-group proposal to explain how all selected changes serve one concrete purpose.
- Preserve planner evidence, exact selections, rationale and pending repartition decisions through commit construction. Publish only after every requested group has a verified commit, retaining completed commits if a later group fails.

### Fixed

#### Validation

- Accept an observed exclusive-create collision refusal in Windows junction probes while preserving null-handle checks and verifying that no file is created in either the redirected target or the original directory.

## Validation and save limits

[Release preparation](../../tests/integration/distribution/evaluations/2026-11-07-preview13-release/preparation.md)
records source validation. [PW-06 evaluation](../../tests/skills/git_publish_work/evaluations/2026-11-06-intent-partition.md)
records the separate assistant planning handoff and independent Git observations.
The unchanged baseline also split the PW-06 edits. This case confirms one
application of the revised flow and does not establish a reproduced baseline
failure or universal agent reliability. The Python control verifies Git
mechanics using a prescribed partition.

Native client activation retains its existing evidence limits. Activity-report
default saves still require a demonstrated guard against concurrent hard links.
On NTFS, normal native handles alone do not supply it. Without an adequate
guard, the default save fails before directory or file mutation. Explicit
user-selected destinations retain the report writer's one-file contract and
existing-parent requirement. The [preview.12 save limits](v0.1.0-preview.12.md#validation-and-save-limits)
retain the original scope.

## Publication checks

Require candidate and merge tree equality. Compare every ZIP file with its Git
blob, run extracted repository and distribution validators, compile packaged
Python sources without execution, and check the twenty-skill inventory.
Independently download the uploaded draft assets and compare their hashes
before publication. Confirm the public tag and the actual GitHub publication
date in America/Mexico_City. Preserve existing releases, tags and assets.
