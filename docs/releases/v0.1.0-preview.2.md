# Devcraft Toolkit v0.1.0-preview.2

Experimental remote-suite distribution, prepared in PR #4 with its changelog and
release metadata in the same merge. The GitHub release tag must target that merge
commit; no follow-up release-preparation commit on main is required.

Seven skills are available and ten catalog capabilities remain planned. Native
plugins/Powers and complete skill sets expose the same canonical resources;
delivery, scope and lifecycle differ by client. Crew uses its own importer and
existing agent, without a toolkit template or App.

See the [changelog](../../CHANGELOG.md), [installation overview](../installation.md)
and [compatibility evidence](../compatibility.md).

## Downloads and integrity

Download `devcraft-toolkit-v0.1.0-preview.2.zip` and `SHA256SUMS.txt` from
[the GitHub release](https://github.com/omarfrancodev/devcraft-toolkit/releases/tag/v0.1.0-preview.2).
Verify the ZIP's SHA-256 against that file before extraction. The ZIP is a
source/package archive of the exact tagged merge commit, including canonical
skills, manifests, docs and external tests. It excludes Git internals, ignored
worktrees, caches, temporary files and generated distributions.

For example, PowerShell `Get-FileHash -Algorithm SHA256` or a platform's
`sha256sum` can calculate the download digest. Consumers normally use the
remote installation routes; manual copies must include complete skill folders
and every required dependency.

## Validation boundaries

Prior Codex/Claude/Copilot remote probes establish only their recorded versions,
revisions and narrower acquisition/resource observations. They precede the
root activation-keywords correction and do not prove this release's native
loading. Kiro metadata now follows the documented keywords requirement, but
actual IDE/CLI activation remains pending.

Authenticated invocation, model-driven resource reads, active project/control
isolation, repository auto-install, VS Code crossover, Crew trust/agent sessions,
and version-changing cross-scope lifecycle remain open where recorded.
Project-only native Kiro Power is not_supported; the project skill-set route is
separate. Task 4 Step 3 stays open. This is a pre-release, not stable or complete
seven-client compatibility.

## Publication procedure

Prepare the versioned changelog, both manifest versions and these consumer docs
on the PR branch. Verify the tree, then merge PR #4 with an expected-head guard.
Build the ZIP from that exact merge revision, verify its entries against Git
blobs, run package checks and publish the pre-release tag/assets at that same
revision. Keep previous release assets and tags unchanged. No automated
installer, release workflow, license or marketplace submission is introduced.
