# Devcraft Toolkit v0.1.0-preview.9

Experimental plugin presentation and skill-selector metadata. The suite retains
eighteen available skills with their existing canonical identities, instructions,
operation authorization and dependency closures. All release preparation is part
of PR #11; the tag and assets must target its exact merge commit.

## 0.1.0-preview.9 — 2026-10-30

### Added

#### Catalog and distribution

- Add an editable Devcraft Toolkit logo and packaged PNG for the Codex listing/composer and Claude directory metadata, with client-specific display names and portable project links.
- Add explicit selector titles and concise UI descriptions to every available skill through self-contained `agents/openai.yaml`, preserving canonical identities and invocation behavior.

### Changed

#### Catalog and distribution

- Classify the Codex and shared Claude/Copilot marketplace entries as `Developer Tools`, add discovery tags and marketplace description, and validate presentation fields and packaged PNG resources. Document the distinct image/category limits for Copilot, Kiro Powers and Crew.
- Require unique, unprefixed skill labels and presentation-only metadata in the distribution validator; cover missing, malformed and policy-changing sidecars without adding placeholders for planned capabilities.

## Downloads and integrity

Download `devcraft-toolkit-v0.1.0-preview.9.zip` and `SHA256SUMS.txt` from
[this release](https://github.com/omarfrancodev/devcraft-toolkit/releases/tag/v0.1.0-preview.9).
Verify SHA-256 before extraction with `Get-FileHash -Algorithm SHA256` or
`sha256sum`. The ZIP contains the exact merged Git tree, including the complete
canonical skills/resources, manifests, documentation and external tests.
Git internals, ignored worktrees/caches and generated distributions are excluded.

## Validation boundaries

[Client metadata](../installation/metadata.md) documents supported fields and
actual limitations. [Retained Claude validation](../../tests/integration/distribution/evaluations/2026-10-30-plugin-metadata/native.md)
accepted the manifest/catalog on Claude Code 2.1.300 in strict mode. Claude's
`icon` is directory metadata, not a runtime icon setting. No undocumented logo
field is added for Copilot or Kiro; Crew still imports skill folders.

The distribution validator requires unique single-line labels and concise
presentation-only descriptions for every available capability, without a fixed
inventory count or planned placeholders. Canonical names, namespaces, policies,
permissions and skill dependencies are preserved. Update/reload and native UI
rendering in Codex and other clients remain separate acceptance checks.

[Fresh release preparation](../../tests/integration/distribution/evaluations/2026-10-30-preview9-release/preparation.md)
records the prepared source's validation and review scope. No public directory
submission, license, custom installer or release automation is introduced.

## Publication procedure

Prepare source, changelog and notes in PR #11. Validate the candidate archive,
merge with a server-enforced expected-head condition and require candidate/merge
tree equality. Build final assets from that exact merge with command-local LF
archive settings. Compare every ZIP member to its Git blob, validate extracted
sources and verify the eighteen skill metadata files. Upload to a draft
prerelease, independently download and digest both assets, then publish and
confirm the tag target and GitHub publication date in America/Mexico_City.
Preserve older releases, assets and tags. Final SHA/digest receipts belong to
release metadata/local artifacts, not a later source-preparation commit.
