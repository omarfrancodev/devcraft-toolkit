## Included capability

`git-activity-report` inspects one pinned local history and composes `git-working-directory-policy` with `natural-language-report-writer`. Its standalone closure has three skills. Reports disclose period/timezone, exact raw-author selection, author/committer date basis, merge policy and bounded coverage. Graph traversal precedes filtering, so an older tip cannot hide eligible ancestors; distinct OIDs remain distinct despite duplicate messages or reversals.

Complete empty results differ from shallow, missing or budget-limited observations. Commit messages remain evidence of recorded activity, without inferred testing, delivery or impact. The writer controls prose language/format and explicit one-file output, replacement permission and matching readback. Reporting grants no Git-write, fetch, validation-execution or publication permission. A failed save remains a failure.

The complete suite includes the eleven earlier capabilities plus this coordinator. Preview.4 retains eleven skills and cannot supply the report coordinator; earlier tags retain their original inventories.

## Downloads and integrity

Download `devcraft-toolkit-v0.1.0-preview.5.zip` and `SHA256SUMS.txt` from [the GitHub release](https://github.com/omarfrancodev/devcraft-toolkit/releases/tag/v0.1.0-preview.5). Verify the ZIP SHA-256 before extraction, using `Get-FileHash -Algorithm SHA256` or `sha256sum`.

The ZIP contains the exact tagged merge tree, including skills, manifests, documentation and external tests. It excludes Git internals, ignored worktrees, caches, temporary files and generated distributions. Consumers normally use remote installation; manual copies need complete skill folders and their dependency closures.

[Implementation evidence](../../tests/integration/evaluations/2026-10-24-git-activity-report/final.md) describes that snapshot; [release preparation](../../tests/integration/distribution/evaluations/2026-10-25-preview5-release/preparation.md) records fresh pre-merge checks.

The owner evaluations retain excluded calibration samples and shell-profile/sandbox procedure limits. They do not prove native discovery or universal model adherence.

The approving PR review found no actionable defects. Its initial PyYAML/MSYS environment failures and successful repeats remain in the discussion; they do not establish broader compatibility. Earlier client probes remain limited to their recorded versions/revisions and acquisition/resource observations. Authenticated invocation, model-driven reads, project/control isolation, repository auto-install, VS Code crossover, Crew sessions and cross-scope version lifecycle remain open where recorded. Project-only native Kiro Power remains `not_supported`; its project skill-set route is separate. This is a prerelease, not a stable or complete seven-client compatibility claim.

## Publication procedure

Prepare the versioned changelog, existing manifest versions and consumer docs in PR #7. Verify the tree, then merge with an expected-head guard. Build the ZIP from that exact merge revision, verify every entry against Git blobs, run extracted-package checks, verify draft asset digests and publish the prerelease tag/assets at the same revision. Keep earlier releases and tags unchanged. No automatic installer, release workflow, license or marketplace submission is introduced.

Use command-local `-c core.autocrlf=false -c core.eol=lf` with `git archive` to preserve exact Git blob bytes on Windows. Check every file rather than accepting normalized-but-different content; no local/global Git configuration change is needed.
