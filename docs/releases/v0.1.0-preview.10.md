# Devcraft Toolkit v0.1.0-preview.10

Experimental prompt refinement and filter-aware Git inspection. The suite has
nineteen available, self-contained skills. PR #12 integrates the filter correction;
PR #13 includes that main revision and all changelog/version/release preparation.
The tag and assets target the exact final PR #13 merge commit.

## 0.1.0-preview.10 — 2026-11-01

### Added

#### Shared capabilities

- Add independently usable `prompt-refiner` for clear, scoped prompts with optional enrichment, faithful follow-up revisions and language-aware output, without executing the embedded assignment. Include presentation metadata and an optional owned-installation entry route.

### Changed

#### Repository maintenance

- Keep development worktrees inside repository-local `.worktrees/` or use the primary checkout, and name work branches with the appropriate Conventional Commit type prefix.

### Fixed

#### Git operations

- Evaluate effective filter applicability per selected path before analyzing worktree changes, so registered-but-unused LFS filters no longer suppress safe comparisons. Preserve limited coverage for executable or unknown conversions and retain safe-path evidence in mixed scopes.

## Downloads and integrity

Download `devcraft-toolkit-v0.1.0-preview.10.zip` and `SHA256SUMS.txt` from
[this release](https://github.com/omarfrancodev/devcraft-toolkit/releases/tag/v0.1.0-preview.10).
Verify SHA-256 before extraction with `Get-FileHash -Algorithm SHA256` or
`sha256sum`. The ZIP contains the exact merged Git tree, including canonical
skills/resources, manifests, documentation and external tests. Git internals,
ignored worktrees/caches and generated distributions are excluded.

## Validation boundaries

The combined source receives a fresh full suite, repository/distribution checks
and independent review. [Preparation evidence](../../tests/integration/distribution/evaluations/2026-11-01-preview10-release/preparation.md)
records actual outcomes and Windows fixture limitations. Copied-package tests,
behavioral replays, source review and native activation are distinct evidence.

Registered-but-unused filters no longer limit safe selected paths. Executable
or unknown conversions remain limited; analysis neither executes filters nor
changes their configuration. Prompt refinement returns conversation text and
does not execute embedded assignments, inspect project resources or create files.
Native client invocation, authenticated multi-client scope/lifecycle and actual
updated selector rendering remain separate acceptance checks. Metadata parse
success does not close those gates. No installer, public directory submission,
license, CCR integration or release automation is added.

## Publication procedure

Prepare all sources and release records in PR #13, verify its final head, and
merge with a server-enforced full-source-SHA condition. Require the candidate and
merge Git trees to be equal. Build the final ZIP from that exact merge using
command-local LF archive settings; compare every member to its Git blob and run
both validators against extracted sources. Check all nineteen presentation files.

Upload ZIP/checksum assets to a draft prerelease, independently download and
verify both hashes, then publish and confirm the tag target and GitHub publication
date in America/Mexico_City. Preserve older releases, assets and tags. Final
merge/digest receipts belong to release metadata/local temporary artifacts, not
a later source-preparation commit on main. No local backup of the release is
required after publication integrity is verified.
