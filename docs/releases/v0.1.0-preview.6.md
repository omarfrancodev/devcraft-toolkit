Experimental scoped branch synchronization and publication, prepared in PR #8 with the changelog and release documentation in the same merge. The tag and assets must target that exact merge commit; no follow-up release-preparation commit on main is required.

Fourteen skills are available and three catalog capabilities remain planned. Native plugins/Powers and complete skill sets expose the canonical resources at the selected revision; delivery, scope and lifecycle differ by client. Crew uses its importer and existing agent without a toolkit template or App.

See the [changelog](../../CHANGELOG.md), [installation overview](../installation.md) and [compatibility evidence](../compatibility.md).

## Included capabilities

`git-sync-branch` performs one explicitly requested scoped fetch and an eligible fast-forward of the current branch. Divergence requires a decision. It preserves ignored-file collisions and rejects symbolic selected tracking destinations before writes.

`git-publish-changes` sends one pinned current-branch OID to one remote branch through a normal push, then independently verifies the effective push endpoint, including pushurl/rewrite handling. Optional upstream setup requires an explicit request, an existing usable fetch mapping/tracking ref, exactly two repository-local branch keys and actual upstream ref/commit resolution. Failed or incomplete setup preserves verified publication and actual state.

Each has an independent three-skill standalone closure with context and safety; neither requires the other. The entry adds optional ownership-aware routing without changing its hard dependencies. Default inspection remains offline. No implicit fetch during push, force, automatic retry, PR, promotion or release follows from these operation permissions. Prior or partial effects stay visible.

The complete suite retains the twelve earlier skills. Preview.5 has twelve and cannot supply the two added capabilities; earlier tags retain their original inventories.

## Publication procedure

Prepare versioned changelog, existing manifest versions and consumer documentation in PR #8. Verify the prepared tree and merge with an expected-head guard. Require the merge tree to equal the prepared tree. Build the ZIP from that exact merge revision, compare every entry with Git blobs, run extracted-package checks, verify draft uploaded/downloaded asset digests, then publish the prerelease at that same revision. Preserve earlier releases/tags. No release workflow, automatic installer, license or marketplace submission is introduced.

Use command-local `-c core.autocrlf=false -c core.eol=lf` with git archive to preserve exact Git blob bytes on Windows. Compare every file; no global/local configuration change is needed.
